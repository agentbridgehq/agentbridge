# Launch drafts

Edit these before posting anything. They are written to be honest rather than
exciting, on the theory that the audience is developers who have been burned by
tools that oversold themselves.

Two rules that should survive editing:

1. **Do not claim client support we have not measured.** Three clients are
   marked `undocumented` for skills. Saying so is the credibility.
2. **Do not describe the control plane as though it exists.** It is a plan in
   [docs/01](../../docs/01-vision-and-strategy.md). What ships is a CLI.

Post the [upstream contributions](../upstream/) first. Arriving in the ecosystem
as someone who filed two specification defects and donated a test suite is a
better introduction than arriving as someone launching a product.
